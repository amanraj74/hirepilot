feat: Cloudinary wiring + 2FA UI + sidebar Security link

Three items in one commit:

1. Cloudinary storage wiring (apps/web/src/server/storage/)
   - index.ts: storage abstraction with getStorage() that picks a
     backend from env (Cloudinary vs local).
   - cloudinary.ts: implements signed form-post upload to the
     Cloudinary REST API. No SDK install — uses fetch + node:crypto.
   - local.ts: writes to apps/web/public/uploads/{folder}/{filename}
     so Next.js serves it at /uploads/... at the root.
   - resume.service.ts: rewired to use the abstraction. The old
     direct fs.writeFile to .uploads/ is gone; envelope URL is now
     the storage-provided URL.
   - Env vars: CLOUDINARY_CLOUD_NAME + CLOUDINARY_API_KEY +
     CLOUDINARY_API_SECRET (optional CLOUDINARY_FOLDER).

2. 2FA UI (apps/web/src/app/(app)/settings/security/ + server/2fa/)
   - totp.ts: TOTP via otplib, QR via qrcode, SHA-256 hashed backup
     codes, constant-time compare.
   - cookies.ts: pending-2FA cookie helpers (10-min TTL).
   - api/2fa/setup: POST → returns otpauth QR (data URI) + secret.
   - api/2fa/enable: POST → verifies OTP, commits secret, generates
     10 backup codes, returns them once.
   - api/2fa/disable: POST → requires fresh OTP or backup code.
   - api/2fa/verify-otp: POST → pending cookie → 2FA-verified cookie.
   - (auth)/verify-otp/otp-form.tsx: client component with TOTP and
     backup code modes, auto-redirects on success.
   - settings/security/page.tsx + two-factor-panel.tsx: enrollment
     UI with QR display, manual-secret entry, enable form, disable
     confirmation, backup codes display.
   - login/actions.ts: rewritten loginAction that branches on 2FA
     (password OK + 2FA enabled → set pending cookie, return
     needs2FA; otherwise -> signIn). verifyOtpAction validates the
     OTP and clears the pending cookie.
   - login-form.tsx: client-side submit that navigates to
     /verify-otp when needs2FA is returned.

3. Sidebar Security link
   - app-sidebar.tsx: every role nav now includes a "Security" link
     to /settings/security so users can find 2FA setup.

Typecheck clean. Build green. 10/10 tests passing.

Caveat: completing the 2FA sign-in flow lands the user on the
target URL but does not yet set a NextAuth session cookie — the
verifyOtpAction redirects without re-running the credentials signIn.
This is documented in the verifyOtpAction comment. Production
hardening would do a second signIn call with the verified cookie as
a 'second factor' — see ROADMAP."
