fix(storage): surface actionable error on Vercel without Cloudinary

The \"Storage upload failed: ENOENT\" on Vercel was because the
local-fs provider tries to mkdir under /var/task/apps/web/public
but the serverless runtime is read-only. The current code would
silently fail with a filesystem error.

Now getStorage() detects the runtime explicitly:

- CLOUDINARY_* env vars set → use Cloudinary
- VERCEL=1 without Cloudinary → throw CloudinaryRequiredError
  with a clear message: set CLOUDINARY_CLOUD_NAME, _KEY, _SECRET
  in Vercel env vars
- otherwise → use local filesystem (dev only)

The error propagates through the resume service as a 503
ResumeUploadError, so the toast on the candidate's screen says:
\"Storage init failed: Cloudinary is required on Vercel — set
CLOUDINARY_CLOUD_NAME, …\" instead of an opaque ENOENT.

Build green."
